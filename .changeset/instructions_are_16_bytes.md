Programs run on smaller instructions and a shorter loop, and the VM does less work for each one: most programs run 10% to 28% fewer machine instructions, and a long function loads several times faster than before. What a program prints does not change. Three limits come with it. A function takes at most 250 parameters and a call passes at most 250 arguments, and the compiler refuses more: in a function, a lambda, a function type or a call, and in a constructor that is read as a function. A constructor of more fields can still be built by name. A function that holds more than 254 values at once loads, and stops the run when it is called, with "cannot run: the new VM does not run main.f, which holds more than 254 values at once, yet"; before, such a function ran. A long array, interpolation or binary literal does not count against that, nor does an array literal with a spread in it, because its elements are put in a piece at a time when they would not fit. `scarlet dis --instrs` prints every instruction the same way, as its name and then its operands in brackets, and it and `scarlet run --counters` name some new ones: those ending in `Wide` hold too many operands for one instruction, `CtorOver` is a constructor that takes a cell kept for it, whose register is listed as `over r0`, and `TailCallSelfKeep` is a loop that carries one to its next turn, listed as `keep r0`. A constant nothing reads, a copy from a register to itself and a jump to the next instruction are left out, so some programs run fewer instructions than they did.
