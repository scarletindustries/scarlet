The VM does less work per instruction. Int arithmetic on small numbers skips the big-number path, a comparison or sum against a small constant is one instruction, an `if` on a comparison compares and jumps in one, and a call no longer allocates for its arguments. `map::set` on a map nothing else holds changes it in place instead of copying the path to the key. `examples/bench_heavy.sca` goes from 0.87 s to 0.40 s, and `examples/bench_map.sca` from 2.60 s to 1.19 s. A call passes on an argument nothing reads afterwards instead of sharing it, and a push onto an array nothing else holds grows it in place, so walking and rebuilding an array is about a third faster. `map::delete` changes a map nothing else holds in place too. An Int just past the small range, up to 64 bits, is added and compared without `num-bigint`, and a constructor no longer allocates for its fields. `map::get` matched straight away makes no `Some` cell, and a map node keeps a little spare room, so a set or delete on a map nothing else holds rarely allocates. A frame holds only the registers its function uses, a call puts its arguments straight into the new frame, and a register is found with one bounds check instead of two.
