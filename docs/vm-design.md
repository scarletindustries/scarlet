# The new VM

This is the plan for the VM that runs a compiled Scarlet program. It lands one small PR at a time, in the order at the bottom, and each step there says how far it has got.

Each point is marked:

- **Decided**: the project has chosen it. Most of these are also in `docs/semantics.md`.
- **Proposed**: a recommendation. It needs a yes before code depends on it.
- **Open**: not decided.

## What the VM is given

The compiler hands over one `core_ir::Program` (`crates/scarlet_ir/src/core_ir/mod.rs`):

| Field | What it is |
|---|---|
| `fns` | Every function, numbered by `FuncIdx`: declared ones, lambdas, and the wrappers the compiler writes when a constructor or built-in is used as a value. |
| `consts` | Every constant, numbered by `ConstId`: Int, Float, String and Binary. |
| `inits` | Each imported module's toplevel, in the order they must run. The prelude comes first. |
| `toplevel` | The entry file's own toplevel. |
| `main` | The function the program starts at. It's `None` for a REPL entry, which runs its toplevel and prints the value. |
| `globals` | How many module-level slots the program needs. Toplevels write them, and functions read them with `Load::Global`. |
| `types` | Every type the program builds or matches a constructor of, by `TypeId`: the type's name, and each variant's name and field labels. The names are only for showing a value to a person (`Some(1)`, `Point{ x: 1, y: 2 }`), and nothing the program *does* depends on one. How many fields each variant has is not only for showing: the loader makes its table of constructors from it, and refuses a constructor or a pattern that is not listed or has another number of fields. |

Each function is a `LoweredFn`: its `module`, its source `name`, its `core` body, and the `pool` that the types in the body are numbered in.

A body is already in A-normal form: every operand is a local, and nested expressions have been flattened into a chain of `Let`s. The whole language comes down to these pieces:

- **Values** (`Atom`): a local, a constant, a global or capture, `nil`, a bool, a constructor, a closure, a primitive op (`PrimOp`, like `IntAdd`), a built-in call (`Intrinsic`), and a call. A call names its target as a known function, the function itself, or a closure held in a local.
- **Control** (`CoreExpr`): `Let`, `If`, `Match`, `Tail` (return a value or tail-call), `LetJoin` (a branch whose value is used), `LetCont` and `Goto` (a shared "try the next case" point for pattern matching), and `Drop`.
- **Memory hints from Perceus**: `Drop x` at the last use of `x`.
- **Bool and Nil are never constructors.** In the source, `True`, `False` and `Nil` are the prelude's constructors. A compiler pass (`crates/scarlet_lower/src/immediates.rs`) turns each one into the `bool` or `nil` value and turns a `match` on a Bool into an `If`, so the VM never needs to know which type is the prelude's `Bool`.

`scarlet dis FILE` prints all of this for any program. `scarlet dis --instrs FILE` also prints, after each function, the register instructions the VM loads it as ("Running code").

## The rule the VM keeps

**Decided.** Code never crashes, and failure is a value. For the VM this means nothing Scarlet code does can take down a process, let alone the program.

The old VM broke this in these ways. The new one must not:

| The old VM | The new VM |
|---|---|
| `xs[a..b]` out of range crashed the process. | Returns a value (the stdlib signature changes with it). |
| A `receive` on another process's subject crashed. | Impossible, or a value. |
| Printing or hashing a deeply nested value overflowed the Rust stack. | Walks values with a loop, the way the old `==` already did. |
| `println` into a closed pipe crashed. | Stops quietly. |
| A huge timeout crashed the scheduler. | The timeout is clamped. |
| Tampered `wire` bytes aborted the program. | `decode` returns `Err`. |
| One process using too much memory aborted everything. | Only that process stops. That's a resource death, not a bug. |
| A bug in the VM itself aborted everything. | Stops only the process it happened in, and says where, straight away. |

**Proposed: the VM never recurses in Rust on anything the program controls.** Call frames live on a stack the VM allocates itself, and printing, hashing, equality and freeing walk values with explicit work lists. Then deep recursion or deep data just uses memory, up to the limits of the stack and the heap, and a program past one of them stops with a message. No stack overflow is reachable from Scarlet code.

## Values

**Decided: every value is one 64-bit word, and floats are stored as themselves.** Floats never allocate. Game servers were named as a target, and they need fast floats.

**Proposed: NaN boxing, like the old VM.** A float's NaN bit patterns hold every other kind of value: small ints, `nil`, bools, and pointers to heap objects. Scarlet has no NaN (below), so every NaN pattern is free for this. The old VM had to tidy stray NaNs first; the new one never meets one.

**Built: the tags.** The table at the top of `crates/scarlet_vm/src/value.rs` is the only place a tag is given out. A small int is `0xFFF8` and up in the top 16 bits. `Nil` and the Bools are under `0x7FF8`, a function with no captures under `0x7FF9`, a cell under `0x7FFC` and a constructor with no fields under `0x7FFD`. `0x7FFE` is kept for a literal frozen in the loaded program, and immediate 3 for the empty array. A cell's word carries which variant its constructor is, in bits 32 to 47, and a constructor with no fields carries its own there too. So the top half of a word says which variant of its type a value is, and a `match` tests one by comparing it with a constant (`JumpUnlessTag`), with no look at the heap. A cell that is no constructor's carries 0. The test does not ask which type the value has, because the compiler has proved that. Every one of these is a quiet NaN, so a float operation handed the wrong kind of word gives a NaN, and one test of its answer catches that. The layout leans on the no-NaN rule harder than the old one did: the NaN an ARM chip makes is the word for `Nil` and the one an x86 chip makes is the word for the Int 0. So `Value::finite`, which refuses a NaN or an infinity, and `Value::float`, which turns one into a Float by the rules below, are the only two ways to make a value from an `f64`.

A map's order does not depend on any of this. The hash reads a value by what it is (`hash.rs`), with its own fixed words for `Nil`, a Bool, a function and a constructor with no fields, so moving a tag moves no key.

**Decided: Int is arbitrary precision.** Small ints live in the word, and big ones are heap objects.

- **Built:** the fast path is a checked add on two small ints. On overflow, the result becomes a big int.
- **Proposed:** a result that fits in the word is always stored in the word. So each number has exactly one representation, and `==` and map keys can't disagree about it.
- **Proposed:** use the `num-bigint` crate, behind our own small `BigInt` module, so the choice can change in one place later.
- **Built:** a small int gets 51 bits, two's complement, so it holds -2^50 to 2^50 - 1. Its word is the one kind with the sign bit set: the 13 top bits are all ones and the number is below them.

**Decided: floats have no NaN and no infinity.** After each float op:

- `x / 0.0` is `0.0`. This has to be told apart from an answer that is too big: IEEE says `1.0 / 0.0` is infinity, and clamping that would give the largest float instead of `0.0`. The instruction divides first, and looks for a zero divisor only when the answer is not finite.
- A result that is too big stops at ±1.7976931348623157e308.
- A result with no answer, like `0.0 / 0.0`, is `0.0`.

**Heap objects**: constructor cells, tuples, closures, strings, binaries, arrays, maps, big ints, and handles like process ids.

## Memory

**Decided: reference counting and Perceus.** There is no tracing GC. Values can't form cycles, so counting frees everything.

**Proposed: the VM counts references itself, and Perceus makes it earlier and cheaper.** This is the split the old VM had:

- Reading a local into an operand takes a new reference. Overwriting a slot, or leaving a frame, gives one up.
- That alone is always correct, whatever Perceus did or didn't insert.
- Perceus's `Drop x` gives the reference up at `x`'s last use instead of at frame exit.
- A tail call hands its arguments on, and gives up every other reference its frame still holds, because the callee takes the frame's place. So Perceus puts no `Drop` of an argument before a tail call. The old VM's self tail call kept its frame and needed one, which its emitter moved past the argument reads; in the new VM that drop would free the argument before the call read it.

This matters because Perceus decides what to drop by type, and it leaves some types alone on purpose: `Int`, `Float`, `String`, and generic type variables (`ResolvedPool::is_heap`). Under this split those are still freed, just at frame exit. A big `Int` is a heap object Perceus never drops, and it's still correct.

**Built:** a read may *move* a reference instead of copying it when it's a local's last use as a call argument, a constructor's field, the array of a push, of a drop from the front or of a write at an index, the value such a write puts in, or the source of a plain copy. That's an optimisation, but it's also what makes a count of 1 mean that nothing else holds the value, so that a callee can change it in place or take it apart. Step 6 says how it works.

**Built: a count that goes wrong stops the run.** A wrong count is a bug in the VM or the compiler, never in the program, and there are two ways for one to be wrong.

- *Too low:* a cell is freed while something still holds it. Freeing a cell zeroes its header, and a live cell's count is never 0, so the heap finds it when that holder next takes another reference to the cell, gives its own up, or asks whether it is the only holder before changing the cell in place. `share`, `release`, `unique` and `discard` return `DeadCell` then, in every build, and the run stops at that instruction with `Broken::DeadCell`. The test costs the common paths nothing: a share adds when the count is above 0 and a release subtracts when it is above 1, and only what is left over is asked whether the count is 0. A long cell's two words in the arena are freed the same way, and a name the arena has no cell for, index 0 or one past its end, reads as a freed cell too. What this does not catch is a freed cell whose space was handed out again before its old holder touched it. That holder then shares or releases the new cell. The audit below is what finds that.
- *Too high:* a cell is never freed. Nothing in an ordinary run looks for it.

**Built: the audit.** `scarlet run --audit` checks the whole heap when the program ends (`Heap::audit`, `heap/audit.rs`). It walks the arena, which must be whole cells from word 1 to its end, each with a header that a cell of its class has. It is told every reference the run holds outside the heap, which is the registers on the stack, the globals and `os.env`'s map, and follows every cell's own. Each must name a live cell, and carry the variant that the cell's class says it has, and each count must be the number of references found. The one cell that is never counted is a constant's, so a constant's cell must have that count and no other cell may. Each free cell must be on the list for its size, once, and each long cell must have a box of its own. So it finds a count that is too low or too high, names the cell, and is not fooled when freed space has been handed out again. Then the run gives up its result, every global, `os.env`'s map and the constants made, and the heap is checked once more. A cell still live after that stops the run with `Broken::CellsLeft`: its count is right and nothing outside the heap leads to it, so it and others hold each other. `scarlet run --audit=each` checks before every instruction as well, so the run stops where a count first goes wrong. The loader puts one `Audit` instruction in front of each of the program's and an ordinary load has none, so the interpreter's loop never asks. The driver's tests start every program through one audited `scarlet run` (`common::scarlet_run` in its tests), every program the VM's own tests run is audited too, and the golden programs of up to 40,000 instructions are run once more with `--audit=each`.

**Proposed: constants are frozen.** They live in an area that is never freed, and they're shared across threads with no counting, as in the old VM. **Built** for a big Int: its cell is made the first time the program reads the constant, with a count that is never changed, and every later read gives the same cell. It is in the process's own heap for now. Strings and binaries are still made each time they are read, until step 25 of `docs/perf-plan.md`.

**Built: freeing a big value is a loop.** "How a heap grows", below, says how it works. **Proposed: the loop can be paused.** Dropping a million-item list must not freeze a scheduler thread. The audit found a large `==` froze one for seconds.

**Decided: a heap per process.** Each process allocates from its own heap, and reference counting runs inside it. This is BEAM's shape, with counting where BEAM has a GC.

- **Why it works:** messages are copied when sent, so every object in a process's heap is reachable only from that process. Only the owner ever allocates or frees in it, so it needs no locks and no atomic counts.
- **A limit is just the heap's size.** A process that passes its limit stops, and that's a resource death, not a bug. Its links hear about it like any other death, as with BEAM's `max_heap_size`.
- **Death frees everything at once:** the heap's arena is returned in one piece, and each long cell's box after it, with no walk over the objects in it.

**Proposed: how.**

- The heap is plain data owned by the process: one arena of words, carved into cells, with a free list per size that runs through the freed cells, and a box for each long cell. So it moves with the process when the process moves to another scheduler thread. The old concern, that allocators like mimalloc tie a heap to one thread, doesn't apply to a heap we own.
- A few things must live outside any one process's heap, because more than one process can hold them:
  - constants, in the frozen area;
  - big binaries, which are shared on send rather than copied, as in the old VM, and counted with atomic counts;
  - handles to OS resources, like sockets and files.
- A process keeps a list of the outside things its heap points to. When it dies, it releases each of them before returning its memory. This is BEAM's "off-heap" list.

**Built: how a cell is laid out.** This is step 11 of `docs/perf-plan.md`. A cell is a header word and then its own words. A header has four parts:

| Bits | What it is |
|---|---|
| 0 to 31 | The count. |
| 32 to 39 | The scan: how many of the words after the header are values. |
| 40 to 47 | The cell's size in words, its header's among them, 2 to 254 for a cell that holds anything. It is 0 for a long cell, whose words are in a box. |
| 48 to 63 | The class: 1 to 14 are the kinds of cell the VM knows, and 16 and up are the program's constructors that have fields. |

- **Nothing but the header comes before the values.** A constructor's words are its fields, a tuple's are its elements, and a closure's are its function, as the value word of a function with no captures, and then its captures. A constructor's field and a tuple's element are read by `Field`, and a closure's capture by `GetCapture`, at its index plus one. Both first ask whether the index is below the scan, and neither asks what kind of cell it is: the type checker has made sure of a `Field`'s, and a call puts nothing but a closure in the register `GetCapture` reads. When the index is not below the scan, the cell may be a long one whose words are all values, and those are read from its box out of line. Freeing a cell in the arena is a loop over the words the scan says.
- **A scan of 0 means the kind is asked.** The cell holds no values (a string, a binary, a big Int, a range, a handle), or it keeps other words in front of them (an array's root and branches, a map's three kinds of cell), or its words are in a box. No index is below 0, so the first two kinds of cell have no field to read, and a long cell has the ones in its box when its kind is all values (a constructor, a tuple, a closure or a leaf). A binary slice starts with the binary it is a slice of, so its scan is 1.
- **A class says which constructor, and the program says the rest.** The loader numbers every constructor with fields of every type the program names. It refuses a mention of one with another number of fields than the program lists, and the constructors the VM builds by itself (`Program::abi`) each say how many they are built with (`CtorOf<N>`), which is checked too. The table from a class to a constructor's type, variant and number of fields goes from the loaded program to the heap. There is room for 65,520 of them. A program with more does not load, and stops with `TooManyConstructors`. Printing, the hash, the JSON encoder and the HTTP built-ins read a constructor's class; `==` compares two. The hash feeds the type and the variant that the table gives, so no map's order depends on a class.
- **A variant is in the name of a cell as well as in its class,** and the two always agree. `Cell` is a cell's index and its variant together, so no code that copies, stores or compares one can lose the variant. The heap gives it one when it makes the cell. A freed cell's space gets a new one when it is taken again, because the cell there may be another variant. Inside the heap, a free list, the list of the dying and an audit's walk name a cell by its index alone, and no value can be made from an index.

**Built: how a heap grows.** This is steps 6 and 7 of `docs/perf-plan.md`.

- **No heap until it's needed.** A process has no arena until it makes its first heap value. One that only does Int maths or waits on messages costs nothing here.
- **One arena.** A heap is one run of 8-byte words, and a cell is named by the index of its header word in it. Reaching a cell is then one bounds check, where a list of chunks took two lookups. A new cell is taken from the free list for its size, and when that list is empty it goes at the arena's end. The arena is a `Vec`. The first cell makes room for itself and word 0, which is 4 words at least, and each time the room runs out it doubles, up to the limit and no further. So a heap that grows to N words has moved about log2(N) times and copied under 2N words in all. When the system refuses a doubling, the heap asks for half as much, and then half of that, down to an eighth of the arena. If that is refused too the heap is full, because smaller steps would move the whole arena once every few cells.
- **A name outlives a move.** Growing can move the arena to a new address. A cell's name is an index and not an address, so it is still good afterwards, and no holder has to be told.
- **A long cell lives outside the arena.** A cell of more than 254 words keeps two words in the arena: its header, and the number of a box of exactly its size that holds the rest. The box is freed when the cell is, and whether the process then gets smaller is up to the system's allocator. 254 is the longest cell a header has room to describe.
- **The arena only grows.** A freed cell's space waits on its size's free list for the next cell of that size, and goes back to the system when the process dies. The list runs through the freed cells themselves: the second word of each names the next, so a heap keeps one number for each size and nothing for each free cell. A cell of one word takes two in the arena so that it has that second word. The numbers themselves are a table that is empty until something is freed.
- **A new cell's words are written once.** One that goes at the arena's end is appended with its real words, and one that takes a freed cell's space is written over it. A long cell's go into its box as they come. The exception is a cell that a copy or a splice puts at the arena's end. It is filled with zeros and then written, because its words come out of the same arena.
- **Freeing is a loop with no storage of its own.** A count is a signed number, and below 0 it means the cell is waiting to be freed. The rest of the count names the next one waiting. So freeing a list of a million cells takes no more stack than freeing one, and no memory. This is what Lean does. Giving one word up may write anywhere in the arena, so the loop cannot keep a view of the cell it is freeing. It copies a wide cell's words out eight at a time instead of looking each one up by itself. One value of a count below 0 means something else: a cell that is never freed, for a constant and for a count that overflows.
- **The limit is 2^31 words, which is 16 GiB,** counting the arena and the boxes together, so a cell's index fits in 31 bits. A heap that would pass it stops the run with `HeapFull`, as running out of memory does. One cell is at most 2^28 words less one, which is 2 GiB.

**What BEAM does.** Checked against Erlang/OTP `master` at `bf52b4d716` (2026-09-21):

- A new process's heap starts at 233 words (`H_DEFAULT_SIZE`, `erts/emulator/beam/erl_vm.h`). A whole fresh process is 327 words, about 2.6 KB on a 64-bit machine (`system/doc/efficiency_guide/eff_guide_processes.md`).
- Heap sizes follow Fibonacci plus one word: 12, 38, 51, 90, 142, 233, 376, 610, and so on. That's about 1.6 times per step, up to 833,026 words (about 6.4 MB). After that, each step adds 20% (`erts_init_gc` in `erts/emulator/beam/erl_gc.c`).
- When a heap has no room, BEAM allocates a separate heap fragment of exactly the size needed (`erts_heap_alloc`, `erts/emulator/beam/utils.c`). A message that can't go straight into the receiver's heap goes into one too (`erts_try_alloc_message_on_heap`, `erl_message.c`).
- The Fibonacci table only sizes the main heap at the next collection, which copies everything alive into one block. At that point a heap grows to the next size that fits, and shrinks when it's using under 25% (`erl_gc.c`).

**Why we differ.** BEAM's copying GC moves each value, so it can put a heap back into one block of a size it chooses, and shrink it. Reference counting never moves one value past another, but the whole arena can move, because nothing holds an address into it. So our heap is one block too, grown by doubling where BEAM steps by about 1.6 and then by 20%. We keep an exact-size block only for a long cell, which is BEAM's fragment. What we give up is shrinking: our arena gives nothing back until the process dies.

**Open: fragmentation.** Freed cells leave gaps that a copying GC would squeeze out, and we can't. A gap is only filled by a cell of its own size, and the arena never gets shorter. BEAM hit its own version of this: shrinking hibernated heaps in place "caused serious fragmentation problems when large amounts of processes were hibernated", so `hibernate` now copies what's alive into a new heap of exact size (`garbage_collect_hibernate` in `erl_gc.c`). We should measure the gaps once processes exist.

## Running code

**Decided: register instructions, made once when the program loads.** Each Core construct becomes one instruction, or a few. A local is a value, and the loader gives each value a register: `Let x = IntAdd(a, b)` becomes `x = IntAdd(a, b)`. `If` and `Match` become branches, `LetCont`/`Goto` become labels and jumps, and a `Tail` call reuses the frame.

**Built: the instruction** (`code/ins.rs`, with its fields' types in `code/ins/fields.rs`). It is 16 bytes, and a program's instructions are one array, every function's one after another, with a `Halt` at the start that the first frame returns to. A jump names a place in the array, and so does a call to a known function, so the loop looks a function up only to call a value. A function that reads captures finds them only when it runs as a closure, so `emit` refuses a call by name to one, and a program whose `main` is one (`Broken::CalledByName`). One enum, `Ins<R>`, serves the loader and the loop: in `Ins<VReg>` a register is a value's number, a jump names a label and a call names a function, and giving out registers and places turns it into `Ins<Reg>`, where a register is a byte. The type of each field says what the instruction does with it: a `Dst` is written, a `MaybeDst` is written when it names a register and may name none, a `Hit` is written unless the instruction jumps, a `Src` is looked at, a `Shared` is shared, an `Arg` is taken or shared as its `moved` says, and a `Taken` is emptied. A register that a frame's link is in is no value's, so its number is what names none. So the fields are the one list of an instruction's registers and roles (`Ins::operands`). A macro reads it off the declaration, with the instruction's kind, its jump target and its line in the listing. Adding an instruction is one row there and one arm in the interpreter. Operands sit in the instruction. A form that may have more than fit has a second one with `Wide` at the end of its name, whose operands are a list beside the code. Strings, binaries and the reasons an instruction stops a run are in tables beside it. An instruction gets its place only when every list it names is there, and one that names a string or a binary that is not there stops the run (`Broken::NoPlace`).

**Built: the loader** is a function of five passes, each of which hands the next a value. `translate` makes a function's `Ins<VReg>` from its Core IR, and picks the specific instructions below. A call in tail position to a function the loader knows is no instruction yet (`Step::TailCall`). `live` goes over them once, from the end to the start, which is enough because every jump goes forward. It keeps what is held at each point, and from that decides which arguments take their register and which values may not share one. A value read on a path that did not write it is found here, because it would be held where the function starts, and such a function stops when it is called (`Broken::ReadBeforeWritten`). So does one whose last instruction may go on past it (`Broken::RunsOff`), since what comes next is another function's code. It also finds each `Drop` whose value every way there has taken, which does nothing, and its value is then not held to it. `alloc` puts the parameters from register 2 on in order. A value that a tail call passes gets the register of the parameter it is for, when nothing it clashes with has it, and each other value the lowest that nothing it clashes with has. But that is kept only when the frame has no more registers than with the lowest one for every value, because each call starts above them and each return gives them up. Values that one instruction writes together clash, whether or not they are read. Registers 0 and 1 are the frame's own and no value gets one. It then leaves out what does nothing: a constant that every instruction reading it holds, a `Drop` of what was taken, a `Move` between two values in one register, and a `Jump` to the instruction that would run next anyway. `moves` makes each tail call the moves and the jump it is, as below. `emit` puts every function in the array. Each pass takes time in proportion to the function's length times how many values it holds at once, so a function of 4,000 locals loads in about a tenth of the work it took when liveness was a set of registers per instruction. The tests run the registers every program in the repository is given, and those of thousands of functions made at random, along every path, and check that each register read holds the value that was meant. They also run what `moves` made of each over registers and what it was made from over values, and check that the two pass and return the same, that each reference is held once, and that no cell is left where the frame that follows does not look.

**Built: a handle that nothing drops is closed when it was before the registers were given out this way.** A value that nothing drops is given up when its register is next written, so a register that is given out another way can move that. Perceus drops nothing inside a join, and no value whose type is a variable. It notes where it leaves out a drop of one that could be a handle, so `LoweredFn::undropped` says that a function has such a value, and in one that does, the tail calls ask for no register, a `Drop` that does nothing still keeps its value's register to itself, and `tail_args` moves nothing. A handle is then closed when it always was. When Perceus walks into joins this goes.

**Decided: a frame holds at most 254 values at once,** because a register is a byte and two of its 256 numbers are for the frame's link and its closure. A function takes at most 250 parameters (`scarlet_ir`'s `MAX_PARAMS`), and the compiler refuses more, and a call, a function type or a constructor read as a function with more. A function that holds more loads as one instruction that stops the run if it is called, until values can be spilled. Long literals do not count against it: when a function does not fit, it is taken through again with its array literals, interpolations and binary literals made 32 elements at a time (`code/literals.rs`), as Lua builds a long table. The elements after a spread go on its end a piece at a time, and those before one are made into an array that is then joined to it. A piece is put on an array's end as one leaf (`array::extend_owned`). A function that fits is never changed, so the cells it makes are the ones it always made.

**Built: the frame** (`frame.rs`). All frames are on one stack of registers, and a frame is its registers and nothing else. Register 0 is its link, one word that says where it returns to: the instruction, how many registers its caller has, and which of them the result goes to. Register 1 is the closure it runs as, in a function that reads its captures or itself, and is empty in any other. Its parameters come next. A callee's frame starts where its caller's ends, and the call copies the arguments there. That keeps the preemption check, and "no Rust recursion" simple, and `internal::stack_depth` is a walk down the links, so it costs more the deeper it is asked. `scarlet dis --instrs` prints the instructions next to the Core IR, so nothing is hidden.

The running frame is seen through a window, which is the 256 registers from its start as one array. A register is named by a byte, so every register an instruction can name is in the window, and the types say so: finding one tests nothing. A read is then one load. A write is one store and gives up the value that was there, which tests whether it is a cell. A call or a return takes a new window, which is one test that the stack reaches that far. A window usually reaches past its frame's own registers, so a frame that ends gives up every cell it holds, and the registers above the running frame hold none. They may hold a number or a `Nil` that some frame left there. Nothing reads one, because the loader refuses a function that reads a value no path wrote.

A stack begins with one window and is made longer as calls need it, by a sixteenth more than they ask for, and it never gets shorter. It is at most 2^32 - 1 registers, which is 32 GiB, because where a frame starts is a number of 32 bits. Past that, or when the system has no more memory to give, the run stops with "the program ran out of stack" (`Stop::StackFull`).

**Built: the loop** (`exec.rs`). It matches each instruction where it is, because a copy would have every field read before the jump that finds the handler, and holds only the place in the code, the running frame's window and where that is on the stack. It borrows the stack as a slice, so the stack cannot move or grow while it runs. A call asks for room before it shares or writes anything. When there is none it leaves the loop (`Pause::NeedStack`), the stack is made longer, and the loop starts again at that call, so no call is ever half done. A process that has to wait, or has run for long enough, will leave the loop the same way. Everything that is not a register is one value, `Rest` (`exec/rest.rs`), and whatever is more than a few lines is out of line there or beside the loop. The heap is the last field of it, so a change to the heap moves nothing the loop reads. Dispatch is 9 machine instructions on ARM, with one indirect branch.

**Built: a run can count itself.** `scarlet run --counters FILE` writes how many times each kind of instruction ran, how many heap cells were made, and how many words the heap grew to. The counts are exact, and the same on every run of the same program with the same input, so they can judge a change where time cannot, and `benches/run.py` prints them for every benchmark. The interpreter's loop does not count each instruction, which would slow every run. Instead a counted run loads the program with one `Count` instruction at the head of each basic block, and an ordinary run loads none. A block is only entered at its first instruction and only left at its last, so once the program has run to its end, each instruction ran as often as its block did. A run that stops early has no counts.

It is not the old bytecode: there's no stack machine. A few instructions do two constructs at once: a comparison of numbers and the `if` that alone reads its answer, a `map::get` and the `match` on its `Option`, a `map::set` or `map::delete` and the drop of the map it was given, and a constructor's pattern and the drop of what it matched. All but the first are read off the Core IR, where the second construct stands right behind the first. For the `if`, the loader takes back the comparison, which is the last instruction it made but for constants, and makes one jump of the two. Nothing goes over the finished list looking for instructions to join.

**Decided: the loader picks a specific instruction from what it knows about the operands**, as BEAM's loader does. Such an instruction is the plain one with a fact the loader already holds built in, which a JIT maps to a template more easily and not less. **Built, for numbers:** each operator on two Ints is an instruction of its own, and so is each on two Floats but `==` and `!=`, which are the ones for any two values. One whose name ends in `K` holds a constant the program spells as its second operand. `IntRSubK`, `FloatRSubK` and `FloatRDivK` hold the first, and `+`, `*` and the comparisons hold a first operand by swapping. No instruction holds a constant beside a Float `%`, `==` or `!=`, one on the left of an Int `/` or `%`, or an Int that is not small, so those keep a register. A constant that every instruction reading it holds gets no register and no instruction. An `if` on an Int comparison, or on a Float `<`, `<=`, `>` or `>=`, that nothing else reads is one instruction, `JumpUnlessIntLt` and its kin. `float::from_int` is an instruction too. **Built, for calls:** a call by name of no more than three arguments has an instruction for its number of them, and it is one that takes every argument (`Call0` to `Call3`) or one that shares some (`Call1Share` to `Call3Share`). The first kind has nothing in it that adds a reference, which is worth 9 machine instructions a call. Any other call counts through its arguments. A function that keeps no closure calls itself by name, and only one that does returns with `RetClosure`. **Built, for new cells:** a constructor of one to eight fields that takes all of them has an instruction for its number of them (`Ctor1` to `Ctor8`), chosen where a call's is, once `live` has said what is taken. One that shares a field counts through them (`Ctor`), and one of more than eight has them in a list (`CtorWide`). A tuple of two and one of three are instructions too (`Tuple2`, `Tuple3`). A tuple's elements and a closure's captures are always shared. `crates/scarlet_vm/src/code/ins.rs` lists the operator instructions once, by family, each beside its operator. The loader picks its instructions from that list, and the tests run every one in it against its operator's rules.

**Built: how a cell is made** (`new_cell` in `exec.rs`). Every constructor, tuple and closure that an instruction makes new is made by one function, which puts the operands straight from the registers into the cell. It goes over them twice. First it adds a reference for each value that is shared. Then it takes the space of a freed cell of the size, in a straight line inside the loop, or calls out to add the cell at the arena's end or in a box, and only then do the values go from the registers to the cell, with each register that gives its reference up emptied on the way. So a cell that is refused has taken nothing. The references that were added are taken back, every register holds what it did, and the run stops with `HeapFull`. The heap keeps its half of that: whatever it has to ask for, a long cell's box and the stub beside it among them, it asks for before it asks for the first value. A cell the VM makes for the answer of a built-in holds values that are at hand and not in registers, and is made by `Heap::holding`. What a cell of only values starts as is a `Shape`: a constructor's class and variant, a tuple's, or a closure's with its function in front. An operand list is anything that gives its operands in order (`Hands`). The fixed forms give theirs from fields of the instruction, so the compiler knows how many there are and leaves the loop out.

**Built: how a cell is taken apart** (`open` in `exec.rs`, `Heap::open`). An arm of a match that has no more use for the constructor it matched begins by dropping it, because Perceus puts every drop an arm owes at its start. Where each field would be read out with a reference of its own and the cell then given up, the loader makes one instruction of both, `Open`, behind the test of the variant. A field that nothing reads gets no register. The loader looks only at the run of drops an arm begins with, and only when none of those in front of the scrutinee's is of a field, so nothing is released in another order than the Core IR says but a field that nothing reads, which is given up with the cell. An arm that has nothing to keep is only a `Drop`.

When the cell's count is 1 the fields' references move to the registers and the cell is freed. One compare of the header says that and that the cell is the constructor named, with as many fields, in the arena. The space is then the first on its size's free list, and the next constructor of that size takes it in the straight line that `new_cell` has. So a match that rebuilds needs no more room than the value it took apart, and nothing pairs the two: Perceus's reuse tokens, and the instructions that kept a cell for a constructor, are gone (step 13 of `docs/perf-plan.md`). When something else holds the cell, each field that goes to a register gets a reference more and the cell loses one.

One to eight fields sit in the instruction (`Open1` to `Open8`), and more are a list (`OpenWide`). All eight are inside the loop when nothing else holds the cell. When something does, `Open1` and `Open2` are still inside it, and the rest is out of line for the others. `Open1` to `Open8` give the fields their references first, empty the scrutinee's register next, and only then write the registers, each like any other: what it held is given up. So one of them may be the scrutinee's own, and one may hold the other reference to the cell. A freed cell among the fields of a cell that something else holds stops the instruction before anything has changed, when the field has a register to go to. One that has only to be given up stops it once everything else is done. A field that only moves, because nothing else held the cell, is not looked at, so a freed cell there is found by what next takes a reference to it or gives it up. Every other count is right each time.

Every `OpenWide`, a long cell, one that is never counted and one that is not the constructor named go to one function out of line (`open_apart`), which takes any cell. It keeps the cell to the end and goes field by field: a field has its reference, then its register is written, and then what that held is given up. The cell is given up last, so its fields are there until then whatever else held it. At a freed cell among the fields of a cell that something else holds, the fields before it are in their registers, the scrutinee's register has the cell back with the reference it had, and every count is right. What is not the constructor stops the run (`Broken::OpenedOther`) with nothing changed.

**Built: how a number instruction runs** (`int.rs`, `float.rs`). An Int instruction tests that both words are small Ints with one `&`, does the operator on the 51 bits raised to the top of the word, so that the CPU's overflow flag says whether the answer is small, and otherwise calls one cold function that works on Ints of any size. A Float instruction does its operator on the two words as they are and tests only the answer with `Value::finite`. A word that is no Float is a NaN, so it fails that test, as a divide by zero and an overflow do, and one cold function reads the operands again and answers or stops. A Float comparison asks `partial_cmp`, which gives `None` for a NaN. An operator may be a Float instruction only if a NaN operand always gives it a NaN: `min`, `max` and `pow` would give the other operand or 1, so they stay built-ins that check what they are given. An operator typed only as "a number" is one generic instruction (`Num`) that looks at its operands.

**Decided: a JIT comes later.** It compiles the same instructions to machine code, so the interpreter and the JIT agree by construction on what each instruction means. Speed work, JIT included, waits for a benchmark to point at.

**Built: every call is a proper tail call when it's in tail position.** Scarlet programs rely on it (`examples/tco.sca`). How is below: a call of a function the loader knows, and a call of a function value.

**Built: a tail call to a known function is moves and a jump** (`code/moves.rs`). Its arguments go to the registers of the callee's parameters as if all at once, every other register that may hold a cell is given up, from the top down, with a `Drop` each or with one `DropWide` when there are more than two, and the run goes on at the callee's first instruction. A call to self ends in a `Jump` to the function's own start, so a loop is a loop in the listing too. A call to another function ends in `Enter`, which holds the place of that function and first gives up the closure the frame ran as, when it kept one. An argument that is in its parameter's register takes nothing, so a loop like `go(n - 1, acc + n)` is a test, a sum, a subtraction and a jump.

A move is made only when nothing still reads the register it writes. Two or three that take their sources are one instruction (`Move2`, `Move3`), which reads all of its registers before it writes one. So registers that trade places or go round need no register to put one aside, and a longer cycle is a few of them. A value passed to several parameters is moved to one of them and shared with the rest.

What a register may hold is found in one walk over the function's instructions, each of which says whether it makes no cell, a number or anything (`Ins::makes`). The walk also leaves out the `Drop` of a register that can hold no cell. An Int that a turn worked out and did not pass, which is a cell when it is big, is not given up at the end of the turn. It goes when its register is next written, when the function returns, when it makes a tail call through a value, or when it makes one to another function that is known. That last one has to give it up itself, because the callee's frame may be smaller, and the registers above a frame hold no cell. So the walk is made twice for a function that has both kinds of tail call. The first finds the registers any turn may leave an Int in, and at each way out those are given up too. A loop's exit pays for them once and its turns pay nothing. A frame never has to ask for room: every function's registers and 250 parameters are inside the window.

**Built: the arguments of a tail call are computed in the order that moves the fewest** (`tail_args` in `scarlet_lower`, after Perceus). `go(n - 1, acc + n)` computes `n - 1` while `acc + n` still reads `n`, so one of the two would need a move. The pass puts an argument after the last read of what it replaces. It moves only a constant, or an Int or Float operation, which is total, reads only numbers and has no effect, so nothing a program does changes places. None of those is ever dropped, so no drop has to be worked out again, and an argument goes behind the drops of the line it follows. Two arguments that each read what the other replaces stay as written, and so does a call whose new order would hold so many more values that the function might not fit. What is held inside a join is not known there, so around one no more may be held at any point of it: whichever of the join's reads are still to come, what is held for them or past the join may not be more than it was.

**Built: a tail call of a function value** (`TailCallValue`) cannot be moves, because which function it enters, and whether that keeps its closure, is known only as it runs. It reads its arguments into values of its own, gives up what the frame holds and writes the parameters (`Window::rewrite`).

**Proposed: each `Intrinsic` is one Rust function that returns a value and never panics.**

## Where the VM lives

**Decided: a new `scarlet_ir` crate holds the Program types, and `scarlet_vm` depends only on it.** That's the Core IR, `PrimOp`, `Const`, `Intrinsic`, `TypeId` and the type pool. The passes (`lower`, `perceus`) live in `scarlet_lower`, which depends on `scarlet_ir` too.

Everything the VM can see is then in one crate, which is the whole contract between the compiler and the VM. Moving the types took a few PRs with no change in behaviour.

`CLAUDE.md`'s crate-layout paragraph used to describe the old VM, with bytecode, a JIT, and a "language-agnostic" runtime. The new VM runs Scarlet's own Core IR, so it isn't language-agnostic any more, and the paragraph now says so.

## Processes

**Proposed: keep the old design's shape.** That's lightweight processes, typed mailboxes (`Subject`), one scheduler thread per core, preemption by counting "reductions" (units of work), and links, monitors and supervisors for real deaths.

What the audit asks to change:

- Native work is charged per item, so a big `==`, send or free can't hold a thread.
- A dead process says why and where, straight away.
- **Open:** when a program ends. Today it's when every process has ended, which hangs if one never does. The audit's pick is "when `main` returns". Also open: the exit code when `main` returns `Err`.

The first VM PRs run one process on one thread. Processes come after the single-process VM is solid.

## Order of work

Each step is one PR or a few. Each PR removes the `#[ignore]` from exactly the tests it makes pass, so `cargo test -p scarlet -- --ignored` counts what's left: 311 after step 2, 301 after step 4, 300 after step 5, 294 once Bool and Nil stopped being constructors, 293 once constructors were built, 248 once `match` ran, 227 once closures did, 222 once tuples did, 219 once arrays were built, 213 once `xs[i]` ran, 212 once slices returned a `Result`, 208 once ranges ran, 204 once `==` did, 190 once the first built-ins ran, 180 once floats did, 174 once binaries did, 165 once the rest of `scarlet/binary` did, 163 once `string`'s built-ins did, and 160 once the bitwise ones did. (Each count is one higher than first written: one Linux-only network test, which skips itself on a Mac, was parked late.)

1. The `scarlet_ir` crate. **Done.**
2. A VM that runs `pub fn main() { println(1 + 2) }`: the value word with small ints only, Int operations, calls, `Println`. `scarlet run` uses it. **Done.**
3. Control flow: `If` and `LetJoin`. **Done.** `Match` and `LetCont`/`Goto` come with constructors, which most matches are over.
4. The per-process heap and reference counting, so there is somewhere to put a heap value. **Done** for one process, with strings as the first heap value: the smallest one, and enough to run `examples/hello.sca`. The limit comes with processes.
5. Big ints. Moved up: when step 2 landed, 119 of the parked tests stopped at a 64-bit constant, most of them in a stdlib module's toplevel (`int::max_value` and the like), before the test's own code ran. **Done.** Those 119 then stopped one step later, at a constructor, so constructors are next. An Int *literal* past 64 bits is still a compile error, because the compiler keeps Int constants as `i64`; that is the compiler's to fix.
6. Constructors, tuples, fields, then Perceus's `Drop` and reuse. The allocation-count tests come back here. Constructors are built, freed and printed: **done**. A constructor with fields is a heap cell, and one without is a value word of its own, like `True`. `match` on constructors, Ints, Floats and strings, its jumps between cases (`LetCont`/`Goto`), and reading a record's field: **done**. The instruction never checks the variant: a field is found by name (`docs/semantics.md`, "Fields"), and when the variants hold it in different slots the compiler reads it through a `match` on the variant instead. A `..base` spread reads the fields it leaves out the same way. Each arm is a test that jumps to the next arm when the value doesn't fit, and for a constructor the test is one compare of the value's word. Tuples: **done**, a cell of their elements, read with the same instruction as a constructor's fields. Perceus's reuse of a cell in place was built and has gone: an arm that is done with what it matched takes the cell apart, and the next constructor of its size has the space ("Running code"). `scarlet/internal`'s `cells_made` counts every cell made. That needs the last reference, and in a walk over a list a call that shared its argument and gave it up only after returning would keep one. **Moves on last use**: a call followed by the `Drop` of one of its own arguments hands the callee the reference the register holds rather than adding one, so the callee is the only holder and may take the cell apart or change it in place. The `Drop` stays where it is and finds the register empty, so a jump that lands on it without the call having run still releases what is there. With it, a walk that rebuilds a list puts each cell where it took one apart: `add_one` over 1000 `Cons` cells makes 1000 and the heap does not grow. A plain copy moves the same way: `Move { dst, src }`, whose `src` is an `Arg`, is what `y = x`, a branch that ends in a name and a pattern that binds the whole value load as, and when nothing reads `src` afterwards `dst` takes the reference `src` held. So `ys = if c { t = fresh(n) ... t } else { ... }` leaves the array with one holder, as the same branch ending in `fresh(n)` does, and a push onto `ys` writes in place either way. An `Open` of the source counts as a read, where a `Drop` does not, so a value the frame takes apart later is shared and not taken.
7. Closures that capture, and calling a function value. **Done.** A closure with captures is a heap cell (its function, then its captures); one without is a value word. A frame of a function that reads its closure holds it, so a lambda calling itself keeps its captures. What the parked tests stop at next: arrays (33), binaries (31), `wire` (17), processes (about 24), and floats (13).
8. Floats with the no-NaN rule. **Done** (`float.rs`): every Float goes through `Value::finite` or `Value::float`, so none is NaN or infinite; `x / 0.0` is `0.0`, `x % 0.0` is `x`, and an answer too large stops at the largest Float. The operators whose operand type is only "a number" (`Add`, `Lt`, ...) pick Int or Float when they run.
9. The rest of strings, then binaries (with binary patterns), arrays and maps. Binaries: **built** (`binary.rs`), as the old VM had them: bits counted from the top of the first byte, literals of Int, binary and UTF-8 segments, patterns, and `<<1, 2>>` printing. A slice, from `binary::slice_bits` or a pattern's `rest:binary`, is a cell pointing into the binary it came from, so it copies nothing, as the stdlib promises; a slice of a slice points at the original. `scarlet/binary`'s built-ins all run; the ASCII ones read whole bytes only, as the old VM's did. A `Radix` reaches the VM through `Program::abi`, which the compiler fills by name when the program loads `scarlet/binary`, so nothing reads a constructor's name at run time. Still to come for them: sharing big ones between processes. **Decided:** an array stays the RRB tree the old VM had (`seq.rs` on master): fast at both ends, fast to index, join and slice. Scarlet code uses arrays like lists (walking with `[h, ..t]`, appending in `array::map`, prepending in `reverse`), and only the tree is fast at all three. `[h, ..t]` should give a view of the same tree rather than a copy. Arrays are **built** (`array.rs`): building, length, walking, pushing at either end, joining and `xs[i] or d`, every operation copying only the path it touches. `xs[i]` builds an `Option`: the `Program` names the stdlib constructors the VM builds itself (`Program::abi`: `Some`, `None`, `Ok` and `Err`), as the old VM's `AbiSlot` table did. `xs[a..b]` returns `Result(Array(a), Nil)`, `Err(Nil)` when the range is out of bounds (`docs/semantics.md`, "Arrays"): **built**. A range `a..b` stores only its two ends, as the old VM's did: its length, elements, tail and slices come from them, and adding to one or joining it builds it as a tree first (`array::Seq`). **Built.** `==` is structural, as the old VM's was (`eq.rs`): the same number, string or constructor with equal fields, arrays and tuples with equal elements, a range equal to the array of its Ints, the same function over equal captures. It walks a list of pairs, not the stack. **Built.** `[h, ..t]` is cheap: an array root counts the items left behind at the front of its head leaf, so dropping from the front keeps the same leaf, and a spent head is refilled by moving the tree's leftmost leaf up whole. Walking an array cuts the tree once a leaf rather than once an element, and copies nothing. Still to come: the same for a `..base` view. **Built:** a write at an index. `array::put` and `array::set` load as one instruction, `ArraySet { dst, src, index, value, miss }`, which has a *miss edge* as `MapFind` has, and is the first whose operands are taken on one edge only: when the array has no such index it writes nothing, takes nothing and continues at `miss`. For `put` the code there copies the array to `dst`, and for `set` the hit builds `Ok` and the miss `Err(Nil)`. The write is handed one reference to the array, the register's own when the loader saw that nothing reads it after a hit, and walks from the root to the slot. A node whose count is 1 is written where it is, and any other is copied first, with the copy put in its place in the node above. So an array with one holder changes in place and makes no cell, and one something else holds has its root and one node a level copied (`set` in `array.rs`). Liveness reads such an instruction edge by edge: its register is written, and its operands taken, only on the way to the next instruction, so what the code after a miss reads does not stop the write taking the array. That holds for `put`, whose miss code is its own. It does not yet hold for `set`: the `Ok` and the `Err(Nil)` join before the program's `match` on them, so an `Err` arm that reads the array is reached from the hit edge too, and the write shares the array and copies. A test pins the count (`a_checked_write_copies_when_its_err_arm_reads_the_array`), and it goes when a match on the call loads as the two edges. Maps: **built** (`map.rs`), a persistent hash array mapped trie in the CHAMP form (Steindorfer & Vinju, 2015). A `set` or `delete` copies only the nodes on the path to its key, about 4 for a million entries, and shares the rest with the map it came from. CHAMP's shape depends only on what the map holds, so two equal maps have the same nodes: `==` compares them node by node, and they list their entries in the same order. A key's hash (`hash.rs`) reads the value as `==` does, so `0..3` finds `[0, 1, 2]` and `-0.0` finds `0.0`. It is SipHash-1-3 with a fixed key: fixed so the order is the same on every run, and SipHash so that knowing the key does not help anyone make many keys share a whole 64-bit hash, the one case where a map slows down. The old VM hashed with FNV-1a. `os::env` is one of these maps too (step 12).
10. The rest of the intrinsics, one stdlib module at a time. A built-in the VM runs is a `Builtin` instruction, and `built` in `code.rs` lists which ones, with their arities. A few have instructions of their own instead, such as `println`, `array::put` and `float::from_int`. A function calling any other still loads, and stops when it runs.
11. Processes: mailboxes, the scheduler, preemption, then links, monitors and supervisors.
12. IO (files, sockets, TLS, HTTP), `os`, and `wire` after its redesign. Files, the clocks, random bytes and `os`: **built**. The VM reaches the world outside only through the `Host` trait (`host.rs`): its arguments, environment and output, the clocks, random bytes and files. The driver makes one and hands it to `scarlet_vm::run`. `OsHost` (`os_host.rs`) is the one for a program on an operating system, and the only code in the VM that calls the OS, so the same interpreter can later run with no OS under it, as MirageOS does for OCaml. Each way out is a `Host` method, and a host gives typed errors (`IoError`, `NetError`, `TlsError`), which the VM turns into the stdlib's values. Sockets, TLS and address lookup: **built**. A listener, a connection or a TLS session lives in the host, and the program holds a handle cell (`Kind::Handle`) holding the host's number for it. When the last reference to a handle cell goes, the heap lists its number, and the VM hands it to `Host::release` at the next network built-in and at the end of the run, so a socket the program forgets is closed. With no scheduler, every wait blocks the thread, and a deadline becomes the socket's own timeout; `OsHost` flushes the program's output before each wait, so a server's "listening" line reaches its reader. TLS is rustls on aws-lc, trusting the machine's store first and webpki-roots' bundle when it has none, as the old VM did. `net.give`, `net.serve` and `http.serve` wait for processes. Ports (`scarlet/os/port`): **open**. A file read or write runs on the one thread and waits for the OS: with no scheduler yet there is nothing else to run. When processes come, these move off the scheduler's threads, as the old VM's blocking pool had them. The OS errors `scarlet/io`'s `IoError` names reach the VM through `Program::abi`, as `Radix` does. `os::env` is a plain map, made the first time a run asks for it and shared after: nothing in a Scarlet program can change its environment, so a map read once says the same as the old VM's live view did, and a map has one form in the VM rather than two. **Open:** backing it by the live environment instead, which is what it is. `scarlet/crypto`: **built**. **Decided:** every crypto primitive is a binding to a well-trusted library, never our own: the digests, HMAC, `const_eq` and signature checks are aws-lc's (`aws-lc-rs`, the provider rustls uses), and random bytes the OS's (`getrandom`). The stdlib's SHA-1, once written in Scarlet, is aws-lc's too. A digest or tag is over bytes, so a binary that is not whole bytes has none, `Err(Nil)`; `const_eq` compares bits, where the old VM dropped a last partial byte and called `<<1, 2:4>>` and `<<1, 3:4>>` equal. `scarlet/json`: **built** (`json.rs`), the old VM's design. `simd-json` parses a document into a compact tape of 16-byte nodes and a string arena, both binaries inside an opaque `Doc`, and every read walks the tape in place (`binary::word` reads a node's two words as they are in the binary's cell), so reading six fields of a large payload copies six strings and nothing else. `Doc`, `ParseError` and `Json`'s constructors reach the VM through `Program::abi`. An `Int` has no bounds, so every integer the parser takes is one, where the old VM's `json::int` refused anything past `i64::MAX`. **Open:** an integer past 64 bits does not parse at all, since `simd-json` has no wider integer. `scarlet/http/h1`'s parsing and `scarlet/http/headers`' lookups: **built** (`http.rs`). A head is read by `httparse`, the parser `hyper` uses, rather than the old VM's own scanner: **decided**, for the same reason crypto is bound rather than written. What the stdlib promises beyond that parse is ours, around it: CRLF-only lines, at most four empty lines before a request and none before a response, the 64 KiB cap, which status each refusal is, the `Connection` and `Expect` tokens, a body's framing, and the chunked-body loop, whose size lines `httparse` reads. It is stricter than the old scanner in four places, each as RFC 9110 or 9112 allows: a token after the version is 400 (it was 505), a bare LF or CR is 400 at once (the old head never ended and waited out its deadline), a NUL in a field value is 400 (it parsed), and a `Content-Length` past 9223372036854775807 is refused. The method, target and fields come back as slices of the buffer the program read, so a head costs its fields' small cells and nothing else; httparse reads a copy of at most 64 KiB of it. The descriptor builder (`typed_ir/wire.rs` on master, removed with the old VM) comes back, and its descriptors reach the VM through `scarlet_ir`: today's Core IR says only `WireDecode(%0)`. **Decided:** a closure on the wire names its code, not its run: its module, its function and a fingerprint of the module's code, as BEAM's `NEW_FUN_EXT` does with the module's MD5. So the same code can decode it after a restart or on another machine, and changed code is a decode error. Handles (`Pid`, `Subject`, sockets) stay tied to the run that made them.
